# Tasks API credential provisioning

`services/tasks-api/.env.prodlike` is generated by `scripts/dev/up.sh`. It is
not the source of truth for approval users or service credentials, and manual
edits to it are lost the next time the dev stack starts.

The machine-local source of truth is:

```text
services/tasks-api/.env.prodlike.local
```

That file is git-ignored because it contains secrets. The tracked half of the
contract is the explicit local-override allowlist in `scripts/dev/up.sh`.
`TASKS_API_APPROVAL_USERS` and `TASKS_API_APPROVAL_SERVICE_CREDENTIALS` must
remain in that allowlist or regeneration will silently omit the local values.

## Provision or rotate credentials

1. Update both approval variables in
   `services/tasks-api/.env.prodlike.local`:

   ```dotenv
   TASKS_API_APPROVAL_USERS=<JSON array of browser approval users>
   TASKS_API_APPROVAL_SERVICE_CREDENTIALS=<JSON array of service credentials>
   ```

   Preserve every active actor when adding or rotating one. Do not replace the
   list with only the actor being changed.

2. Confirm `scripts/dev/up.sh` still allows both variable names through
   `append_env_local_overrides`. If a new generated secret variable is added,
   update the allowlist in the same PR that documents the new local value.

3. Validate JSON before restarting, without printing token values:

   ```bash
   set -a
   source services/tasks-api/.env.prodlike.local
   set +a

   printf '%s' "$TASKS_API_APPROVAL_USERS" | jq -e 'type == "array"' >/dev/null
   printf '%s' "$TASKS_API_APPROVAL_SERVICE_CREDENTIALS" \
     | jq -e 'type == "array" and all(.[]; (.actor | type == "string") and (.token | type == "string") and (.approvalTypes | type == "array"))' \
     >/dev/null
   ```

4. Regenerate the prodlike environment through the normal stack command:

   ```bash
   make up MODE=prodlike
   ```

5. Verify the generated file contains both keys and the expected actor names,
   without logging tokens:

   ```bash
   grep -q '^TASKS_API_APPROVAL_USERS=' services/tasks-api/.env.prodlike
   grep -q '^TASKS_API_APPROVAL_SERVICE_CREDENTIALS=' services/tasks-api/.env.prodlike

   value=$(sed -n 's/^TASKS_API_APPROVAL_SERVICE_CREDENTIALS=//p' services/tasks-api/.env.prodlike)
   printf '%s' "$value" | jq -r '.[].actor'
   ```

6. Exercise one authenticated read/write path per affected actor. A successful
   read alone is insufficient: the 2026-08-20 incident preserved service
   availability while mutation auth failed for seven of eight agent identities.

## Two-file invariant

Changes to this credential path have two inseparable halves:

- **Tracked behavior:** `scripts/dev/up.sh` must merge the relevant variable
  names from the local override file.
- **Machine-local data:** `services/tasks-api/.env.prodlike.local` must contain
  the complete current values.

A PR can only contain the tracked half because the local file contains secrets.
Its rollout notes must explicitly require the paired local update. Do not merge
or deploy an allowlist change under the assumption that the local file was
updated elsewhere; verify it on the target host.

## Recovery

If regeneration drops actors:

1. Restore the complete credential arrays in `.env.prodlike.local` from the
   approved secret source.
2. Confirm the two variable names are present in `up.sh`'s allowlist.
3. Re-run `make up MODE=prodlike`.
4. Verify actor names and authenticated mutation access as above.
5. Do not patch `.env.prodlike` as the durable fix; it will be overwritten.
