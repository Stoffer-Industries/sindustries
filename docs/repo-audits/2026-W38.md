## Audit Report

Severity describes repository risk; **Fact** means directly observed, **Judgment** explains priority or consequence. Findings are severity-ordered within each dimension. No finding below asserts that a secret leaked or a live exploit succeeded.

### Security and dependency exposure

**F0 — [High] Known dependency advisory backlog remains.** **Fact:** `npm audit --package-lock-only --ignore-scripts --json` against this snapshot returned 87 affected package entries: 2 Critical, 23 High, 61 Moderate, 1 Low (exit 1 indicates findings, not a failed registry request). Examples: root `tar` 7.5.16 (`package-lock.json:19221`), Jaeger propagator 2.7.1 (`package-lock.json:6242`), root Vitest 4.1.10 (`package-lock.json:20600`), and a separate old Vitest range in Budget domain (`packages/budget-domain/package.json:15`). Relevant advisories include [tar hardlink traversal](https://github.com/advisories/GHSA-34x7-hfp2-rc4v), [Jaeger malformed-header DoS](https://github.com/advisories/GHSA-45rx-2jwx-cxfr), and [Vitest UI arbitrary file access/execution](https://github.com/advisories/GHSA-5xrq-8626-4rwp). **Judgment:** build/developer tooling and runtime dependencies need separate reachability analysis; an installed package is not proof the vulnerable feature is exposed. High priority because the graph includes both toolchain and server dependencies, not because all 87 entries are independently exploitable. `tracked-code-task` — ➡️ Tracked by task **37f4d7d2 (37f4d7d2-9ec6-4794-b7a8-5302cb61200c)**, already open with matching counts and upgrade ACs. The existing task requires a reviewed design and a human decision on major upgrades/overrides; this audit does not authorize those upgrades.

**F1 — [High] Secret scanning is advisory rather than an enforced server-side gate.** **Fact:** `.github/workflows/ci.yml:660` runs gitleaks with `continue-on-error: true` at line 662; comments at lines 646–653 explicitly defer enforcement pending license setup. `.gitleaks.toml:26` also exempts entire example/test paths, not merely empty placeholder values, despite the narrower prose description. **Consequence/judgment:** a scanner failure or finding need not fail this CI job, and excluded paths can hide non-placeholder values. A local hook cannot substitute for a mandatory server check across all writers. No actual leaked credential was verified, and org rules/secret provisioning were not inspected. `needs-human-decision`: choose the licensed action or a supported license-independent CLI gate, confirm required-check policy, and review exemptions (Q1). Related existing runtime-security work: task **206927ed (206927ed-d851-47af-8864-0056487e0c4e)**; not claiming its current ACs implement this exact follow-up.

**F7 — [Low, conditional] Generic tweet publishing remains outside the scheduler mutation-auth gate.** **Fact:** authentication covers `/items` and `/reorder` (`services/content-scheduler-api/src/app.ts:133`), whereas `xTweetRouter()` is mounted independently at line 146; its POST invokes the publishing client (`services/content-scheduler-api/src/routes/xTweet.ts:44`, `:90`). Its localhost-only warning still names Tasks API and port 4001 (`:29`), even though this is now a scheduler service. **Judgment:** this becomes an unauthorized publishing risk if its HTTP listener is reachable by untrusted callers. The checked-in Fly worker has no HTTP service (`infra/cloud/fly/auto-post-worker.fly.toml:3`); actual local/LAN exposure was not tested, so this is not rated as a confirmed public vulnerability. `needs-human-decision`: approve caller migration/auth hardening before any HTTP exposure (Q2); no duplicate implementation task until that scope is settled.

**W37 security progress, verified in source:** `/oauth/register`, `/oauth/authorize`, `/oauth/authorize/decision`, and `/oauth/token` now mount `oauthRateLimit` (`services/gymtrack-mcp/src/app.js:368`, `:417`, `:451`, `:519`). ## Improvement Strategy

1. **Close the dependency exposure loop.** Target: every Critical/High package has a supported remediation or explicit exposure-based disposition. Prioritize reachable runtime paths and risky build inputs before cosmetic version uniformity. Done: zero Critical and zero unreviewed High findings, affected suites/builds pass, and residual accepted risk is documented under task 37f4d7d2.
2. **Make the released graph the tested graph.** Target: frozen installs and deploy filters that cover every build dependency input. Principle: test, release, and rebuild should agree on dependency resolution. Done: all four affected workflows respond to a root-lock change; MCP image installed versions match the lockfile; unrelated docs remain filtered out.
3. **Make verification claims accurate.** Target: mandatory secret scanning once the delivery choice is settled, plus real Budget DB integration and declared domain/mobile checks. Done: a synthetic scanner canary fails CI, excluded-path policy is reviewed, cross-user DB tests execute after migrations, and CI names reflect what actually ran.
4. **Maintain an evidence ledger instead of inheriting confidence.** Target: task links for behavior-sensitive work and factual onboarding. Done: F2–F4 link implementation PRs on completion; docs distinguish staging, production targets, and unverified runtime properties; obsolete lockfile removal follows documented install ownership.

**Trade-offs:** no big-bang TypeScript strictness migration, blanket dependency auto-fix, new distributed rate-limit infrastructure, or speculative service rewrite. Do not remove legitimate standalone npm locks merely to achieve a single-file slogan. Preserve mocked unit contracts while adding a small real-DB safety net; do not replace fast tests with a large slow integration suite. Human-dependent scanner/exposure choices remain decisions, not implied authorization to reconfigure production.
