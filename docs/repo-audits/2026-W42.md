## Audit Report

Facts below are directly observed; impact/severity statements are engineering judgments. No verified Critical-severity exploit was established.

### Code quality and error containment

**F1 — Budget async failures bypass the Express error boundary — High — `tracked-code-task`.** ➡️ Tracked by task de9d8594 (`de9d8594-4825-40f5-bfb3-30ac31cc50e7`). ✅ [PR #800](https://github.com/Stoffer-Industries/sindustries/pull/800)

- **Fact:** Budget uses Express 4 (`services/budget-api/package.json:28`, locked 4.22.2 at `package-lock.json:14815`). `requireSession` awaits Prisma without a rejection wrapper (`services/budget-api/src/middleware/requireSession.ts:31`); read/write routes do likewise (`services/budget-api/src/routes/transactions.ts:16`, `services/budget-api/src/routes/session.ts:20`). The final error handler exists but does not bridge these rejected promises (`services/budget-api/src/app.ts:84`); bootstrap imports no async-error patch (`services/budget-api/src/server.ts:1`).
- **Consequence/judgment:** DB/network failures can leave requests unanswered and, under normal Node unhandled-rejection behavior, terminate the process rather than produce the intended sanitized 500. The isolated Express probe verified the missing forwarding, not a live-service crash.
- **Action:** add a service-local async boundary to every affected middleware/handler and inject failures in tests. Draft: [Budget error boundary](../specs/budget-api-async-error-boundary-w42-tech-design.md). No Express major upgrade is needed for this fix.

**F5 — Accepted category strings break timeseries aggregation — Medium — `tracked-code-task`.** ➡️ Tracked by task 0a803329 (`0a803329-5666-4dc9-90bc-fd046a730824`). ✅ [PR #818](https://github.com/Stoffer-Industries/sindustries/pull/818)

- **Fact:** PATCH accepts any nonempty category string (`services/budget-api/src/routes/transactions.ts:37`). The reducer combines `day|category`, splits on `|`, and writes to a normal object's inherited key space (`services/budget-api/src/routes/categories.ts:32`).
- **Reproduction:** `food` returned its expected bucket; `constructor` and `__proto__` each threw `series[category].push is not a function`; `a|b` returned a category named `a`. No prototype mutation was demonstrated or asserted.
- **Consequence/judgment:** a valid persisted category can break a user's category chart or silently relabel totals. F1 amplifies the thrown-error impact but is not the cause.
- **Action:** lossless nested maps/tuples and a prototype-safe JSON object; preserve the current ability to store strings rather than silently introducing a restrictive category enum. This is a local corrective task, not code-garden-safe cleanup.

### Architecture and transactional correctness

**F2 — Thread claim commits before its journal exists — High — `tracked-code-task`.** ➡️ Tracked by task 39667e62 (`39667e62-3d23-41d6-87d8-20511ff07091`). ✅ [PR #803](https://github.com/Stoffer-Industries/sindustries/pull/803)

- **Fact:** `claimItem` conditionally updates the item and then inserts the attempt in separate DB operations (`services/content-scheduler-api/src/routes/contentSchedulerThreadPublish.ts:164`). The caller describes them as atomic but invokes them outside the later publishing try/catch (`services/content-scheduler-api/src/routes/contentSchedulerThreadPublish.ts:365`).
- **Reproduction:** the source function, with `updateMany` succeeding and `publishAttempt.create` rejecting, leaves `status=publishing`. Subsequent publish rejects that status (`services/content-scheduler-api/src/routes/contentSchedulerThreadPublish.ts:337`); retry only admits `cleanup_required` (`services/content-scheduler-api/src/routes/contentSchedulerThreadPublish.ts:535`).
- **Consequence/judgment:** a journal insert failure can strand an approved thread before any X request, without recovery through the normal publish/retry paths. This is avoidable local atomicity loss, distinct from the documented unavoidable X-accepted/local-journal crash window (`services/content-scheduler-api/src/routes/contentSchedulerThreadPublish.ts:13`).
- **Action:** short Prisma transaction around conditional claim plus attempt insert, with rollback and concurrent-winner verification. Draft: [atomic thread claim](../specs/thread-publish-atomic-claim-w42-tech-design.md). Do not move X calls into the transaction or blindly reset ambiguous publishing items.

### Security and dependencies

**F4 — Locked dependencies retain critical/high advisories — High — `tracked-code-task`.** ➡️ Tracked by existing task 37f4d7d2 (`37f4d7d2-9ec6-4794-b7a8-5302cb61200c`); no duplicate created.

- **Fact:** registry audit reports **5 critical / 49 high / 68 moderate / 1 low**, counting affected package entries including transitive propagation, not unique exploitable CVEs. Critical-rated entries include `proxy-addr@2.0.7` (`package-lock.json:19887`), `shell-quote@1.8.4` (`package-lock.json:21049`), `tar@7.5.16` (`package-lock.json:21655`), `tinypool@1.1.1` (`package-lock.json:21879`), and Vitest entries at `4.1.10` and `2.1.9` (`package-lock.json:23070`, `package-lock.json:24327`).
- **Examples:** [proxy-addr trust-subnet spoofing](https://github.com/advisories/GHSA-jqcg-44mw-7w3h), [shell-quote command injection](https://github.com/advisories/GHSA-pqg4-j6r4-53mv), [Vitest UI arbitrary read/execute](https://github.com/advisories/GHSA-5xrq-8626-4rwp), [Tinypool prototype-pollution gadget](https://github.com/advisories/GHSA-5gmw-xhrv-c9v3). Preconditions differ; a dependency presence is not proof that a vulnerable feature is reachable.
- **Consequence/judgment:** developer/CI tooling is also a credential-bearing attack surface. Some dependencies enter server runtimes, but production reachability was not established, so the finding is High rather than copying the maximum registry score as demonstrated application severity.
- **Action:** refresh the existing task's baseline and triage runtime versus development exposure before narrowly scoped version changes. Do not bulk-run `npm audit fix --force`; do not introduce another package manager. No license violation or unmaintained-package claim is made without evidence.

**F6 — Secret scanning remains advisory at the workflow boundary — High — `needs-human-decision`.**

- **Fact:** the gitleaks action has `continue-on-error: true`; comments describe a missing-license prerequisite, and the action environment does not explicitly supply `GITLEAKS_LICENSE` (`.github/workflows/ci.yml:884`, `.github/workflows/ci.yml:907`). Whether an org-level secret currently exists was not inspected.
- **Consequence/judgment:** a scanner failure does not fail that job, so listing it in the aggregate cannot make its failure block deployment (`.github/workflows/ci.yml:1004`). Local hooks do not establish server-side enforcement.
- **Action:** decide licensed action versus an approved pinned standalone scanner, then require a synthetic-secret negative fixture to fail the gate. This changes security enforcement; no audit-only code-garden patch or credential provisioning was attempted.

**F8 — Budget bearer sessions have no expiry check — Medium — `needs-human-decision`.**

- **Fact:** the Session model stores a hash and creation time, but no expiry (`services/budget-api/prisma/schema.prisma:53`). Authentication selects only ID/user ID and attaches `expiresAt: null` (`services/budget-api/src/middleware/requireSession.ts:46`). HTTP dev-login is correctly disabled outside development (`services/budget-api/src/routes/session.ts:20`).
- **Consequence/judgment:** a leaked session remains valid while its DB row exists. The deployment population and intended identity migration were not verified, so this is a lifecycle-policy gap, not an allegation of public login bypass.
- **Action:** choose a temporary maximum age/revocation policy or replacement identity plan, including treatment of existing rows, before commissioning migration/security work. Avoid shipping a competing permanent identity system based only on this audit.

No flaky-test or global coverage percentage claim is supported by this run.

### Strengths to preserve

- Distinct service/data owners and mature system-document taxonomy (`README.md:5`, `docs/CONVENTIONS.md:13`). Do not collapse domains to reduce file count.
- Authenticated Budget ownership enforcement, server-side session hashing, and a closed production dev-login route (`services/budget-api/src/app.ts:72`, `services/budget-api/src/auth/session.ts:9`, `services/budget-api/src/routes/session.ts:20`). F1/F8 do not erase those protections.
- Conditional publishing claims and compensating journals are the right primitives; fix the local transaction boundary rather than replacing the workflow (`services/content-scheduler-api/src/routes/contentSchedulerThreadPublish.ts:158`).
- Explicit aggregate/deployment gates and executable infra contract tests already exist (`.github/workflows/ci.yml:980`, `infra/cloud/scripts/tests/ci-deployment-gates.test.sh:79`). Strengthen their inventory rather than adding a second release mechanism.

## Improvement Strategy

| Theme | Target and principle | Measurable completion |
| --- | --- | --- |
| Failure containment at API boundaries | Keep async failures inside the existing HTTP error contract; representation must preserve accepted inputs. | Every Budget async handler is accounted for; injected read/write/auth failures return bounded sanitized responses; special category keys round-trip exactly. |
| Atomic local publishing state | The database owns the claim/journal invariant; external X effects remain outside transactions. | Failed attempt insertion leaves no claim; concurrent claims commit one attempt and one winner, proven against Postgres. |
| Explicit release/security policy | One discoverable required-job set and fail-closed selected controls. | Required/advisory inventory has no unexplained omissions; required-job and scanner negative fixtures prevent deployment; dependency exceptions have exposure rationale and owners. |
| Accurate operating contracts | Describe shipped source truth and explicitly separate runtime evidence and policy decisions. | Both READMEs match mounts/schema; session lifetime policy is recorded before migration; representative latency is measured before performance redesign. |

Trade-offs: do not perform a blanket Express 5 migration, break arbitrary category strings by inventing an enum, auto-retry ambiguous X posts, materialize low-volume analytics prematurely, remove lockfiles without consumer analysis, or undertake a broad file-size refactor. Fix bounded invariants first. Do not treat registry severity alone as production exploitability, but do include credential-bearing build tools in prioritization.
