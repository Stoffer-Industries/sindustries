## Audit Report

### Security and dependencies

**F0 — [High] Dependency advisory backlog needs exposure-led remediation.** **Fact:** `npm audit --package-lock-only --ignore-scripts --json` returned exit 1 with vulnerability metadata and no registry error: 109 total, including 2 Critical and 48 High. Example affected lock nodes include Jaeger propagation (`package-lock.json:6628`), node-forge (`package-lock.json:18694`), tar (`package-lock.json:21611`), and Vitest (`package-lock.json:23017`). **Consequence/judgment:** vulnerable runtime and build-tool paths require separate triage; tool installation alone does not establish production reachability, and the advisory count is not a unique-CVE count. **Classification:** `tracked-code-task` — ➡️ Tracked by task **37f4d7d2 (37f4d7d2-9ec6-4794-b7a8-5302cb61200c)**, verified `open` via Tasks API during this run. Its existing major-upgrade/security decision and tech-design requirement remain in force; no unattended upgrades or duplicate task.

**F1 — [High] Secret scanning can fail without failing the aggregate gate.** **Fact:** the scanner step has `continue-on-error: true` (`.github/workflows/ci.yml:823`) although its job is included in merge-gate (`.github/workflows/ci.yml:917`). The allowlist exempts whole example and service-test paths (`.gitleaks.toml:26`), not merely their empty placeholders. **Consequence/judgment:** scanner failures/findings need not stop deployment, and real values in excluded paths can escape scanning. No actual leaked credential is asserted; the license comment is not proof of current license provisioning. **Classification:** `needs-human-decision` — Q1 selects supported scanner delivery and exception policy before security changes.

No further confirmed injection or unsafe-deserialization defect was established in the sampled routes. This was not a comprehensive secret, license, or exploitability assessment; installed-version freshness and license compatibility beyond the npm advisory query remain unverified.

### Code quality and resource correctness

**F2 — [Medium] Transition requests leave earlier PostgreSQL pools unclosed.** **Fact:** every request constructs a new pool (`apps/mission-control/brainStateApi.js:65`), successful requests replace `activePool` (`apps/mission-control/brainStateApi.js:145`), and shutdown closes only that reference (`apps/mission-control/brainStateApi.js:108`, `apps/mission-control/brainStateApi.js:190`). An injected Pool reproduction issued two successful requests then invoked the close hook: `poolsCreated=2`, `poolEndCounts=[0,1]`. **Consequence/judgment:** ownership of earlier pools is lost; repeated/concurrent requests create avoidable connection churn and lack deterministic shutdown. PostgreSQL idle timeouts may eventually release clients, so this does not prove permanently unbounded open sockets. Scope is the local dev plugin, not a claimed production leak. **Classification:** `tracked-code-task` — ➡️ Tracked by task **55dcd0a2 (55dcd0a2-f66d-450a-8ed3-5f9ca9b3ebf3)**. This localized lifecycle correction is not garden-safe, but requires no service-boundary change or substantial refactor.

### Testing and operations

The checker only evaluates the supplied dependency results (`infra/cloud/scripts/check-ci-results.py:13`); deployments depend on that aggregate (`.github/workflows/ci.yml:932`). **Consequence/judgment:** the checked-in deployment DAG can proceed despite this test failing. Separate live branch rules might still block merging; they were not inspected, and are not assumed to fix the deployment DAG. **Classification:** `tracked-research-task` — ➡️ Tracked by task **9f7dd4e2 (9f7dd4e2-ecc4-450e-9182-72af19e0b0b3)** to inventory required/advisory job policy and live protection before changing the security-related gate.

### Performance and architecture

**F5 — [Low] Local bookmark transitions load complete history per request.** **Fact:** the SQL query has ordering but no window or limit (`apps/mission-control/brainStateApi.js:80`); fallback synchronously reads and parses the entire JSONL file (`apps/mission-control/brainStateApi.js:38`). **Consequence/judgment:** database work, response size and local event-loop blocking grow with history. No current latency regression or production impact was measured. The existing consumers expect an event array, so silently truncating it could corrupt derived metrics. **Classification:** `needs-human-decision` — Q2 establishes supported scale and history semantics before pagination/aggregation work.

The sampled architecture retains domain-specific services and shared packages; no new high-confidence circular dependency or service-ownership violation is established. Route file size alone is not used to justify a refactor.

## Improvement Strategy

1. **Turn security checks into explicit enforceable policy.** Target: every advisory has an exposure/owner decision, and secret scanning fails closed. Principle: a green aggregate is meaningful only when its inputs enforce their stated guarantees. Done: zero Critical and no unreviewed High npm findings; synthetic scanner canaries and scanner errors fail the gate after approved configuration.
2. **Make resource ownership deterministic.** Target: one clear lifecycle owner for every transition pool. Principle: acquire and release at the same scope. Done: repeated, overlapping, failed-query and shutdown tests account for every pool; event ordering and fallback stay unchanged.
3. **Close the gap between verification inventory and release policy.** Target: every verification job is explicitly required or intentionally advisory, with local command scope documented. Principle: enumerate coverage rather than infer it from names. Done: the inventory explains every omission; a failed required-job fixture rejects deployment; `test-all` no longer implies full CI parity.
4. **Set scale contracts before optimizing analytics.** Target: a measured supported history size and a deliberate full-history/window contract. Principle: preserve correctness before capping work. Done: Q2 records row/file-size and latency budgets plus a testable client/server strategy if current limits are exceeded.

**Trade-offs:** do not mass-upgrade dependencies, remove locks, split large route files, or paginate history just to improve audit optics. Do not deploy the dev-only bookmark API as a new service without product/security scope. Do not make all local validation as expensive as full CI merely to justify a target name. Preserve existing domain boundaries and passing deployment-input fixtures.
