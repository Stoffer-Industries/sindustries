# Sindustries Repository Audit — 2026-W39

## Executive Summary

**Health grade: B (engineering judgment):** delivery verification improved materially, but security enforcement and dependency remediation remain incomplete. The top three risks are 84 npm advisory entries (2 Critical, 23 High, 58 Moderate, 1 Low), advisory-only secret scanning, and a Budget OTA selection gap for shared UI/token changes. The consolidated merge gate and existing deployment fixtures are valuable safeguards, but passing fixtures do not prove every deployment input is covered. This is a source/configuration audit of `624e717f`, not a live-service security certification. One new corrective task is fully specified below but could not be created because Rowan's Tasks API credential was unavailable in both native and Gateway execution; the dependency task already exists.

## Audit Report

### Security and dependency exposure

**F0 — [High] Known dependency advisory backlog remains.** **Fact:** `npm audit --package-lock-only --ignore-scripts --json` returned 84 entries: 2 Critical, 23 High, 58 Moderate, 1 Low, with no registry error. W38 reported 87; this is a point-in-time comparison, not evidence that three specific vulnerabilities were fixed. Relevant lock entries include Jaeger propagator (`package-lock.json:6575`), EAS's nested tar (`package-lock.json:13567`), root tar (`package-lock.json:21410`), root Vitest (`package-lock.json:22816`), and Budget domain's separate Vitest (`package-lock.json:24073`). Examples are [Jaeger malformed-header DoS](https://github.com/advisories/GHSA-45rx-2jwx-cxfr), [tar hardlink traversal](https://github.com/advisories/GHSA-34x7-hfp2-rc4v), and [Vitest UI file access/execution](https://github.com/advisories/GHSA-5xrq-8626-4rwp). **Judgment:** prioritize reachable runtime paths and build inputs separately; installing Vitest does not prove its UI server is exposed. `tracked-code-task` — ➡️ Tracked by task **37f4d7d2 (37f4d7d2-9ec6-4794-b7a8-5302cb61200c)**, verified `open`; its existing major-upgrade/design decision is still explicit. No duplicate task or unattended upgrade.

**F1 — [High] Secret scanning is still non-blocking and broadly exempted.** **Fact:** gitleaks retains `continue-on-error: true` (`.github/workflows/ci.yml:794`), even though the aggregate merge gate lists that job (`.github/workflows/ci.yml:890`). No leaked credential is asserted. `needs-human-decision` — Q1: choose supported scanner delivery and verify required-check policy; do not assume the old license comment proves present provisioning.

**F2 — [Low, conditional] Generic tweet publishing remains outside mutation authentication.** **Fact:** scheduler auth mounts cover items/reorder (`services/content-scheduler-api/src/app.ts:133`); the separate tweet router is mounted at line 146 and calls `createTweet` (`services/content-scheduler-api/src/routes/xTweet.ts:44`, `services/content-scheduler-api/src/routes/xTweet.ts:90`). Its trust-boundary comment still names Tasks API/port 4001 (`services/content-scheduler-api/src/routes/xTweet.ts:29`). **Judgment:** untrusted HTTP reachability would allow unauthorized publishing when configured credentials are available. The checked-in Fly worker is explicitly not an HTTP service (`infra/cloud/fly/auto-post-worker.fly.toml:3`); live listener/network reachability was not tested, hence conditional Low rather than an invented public exploit. `needs-human-decision` — Q2: establish the actual caller/exposure contract before migration and authenticated enforcement.

## Improvement Strategy

1. **Remediate exposures, not counts alone.** Target: supported dependency versions and documented disposition of remaining High entries. Done: zero Critical, zero unreviewed High, compatibility tests and full/production-only audit evidence under task 37f4d7d2. Keep runtime telemetry, test runners, and Expo/EAS changes in separate reviewed slices.
2. **Make security gates fail closed.** Target: a supported scanner whose findings/errors fail the required check, with fixture-level rather than directory-wide exemptions. Done: a harmless synthetic canary fails the gate, including currently exempted-path coverage; empty examples pass and branch rules are verified. Q1 gates the delivery choice.
3. **Match release selection to compiled inputs.** Target: every material source dependency selects its consuming release. Done: UI-only and token-only fixtures select Budget OTA; app/domain/root-lock fixtures remain true; unrelated docs remain false. Preserve existing merge/main/environment conditions.
4. **Keep the evidence ledger current.** Target: completed fixes update current onboarding alongside historical implementation links. Done: contributor CI claims match executable jobs, supported lock owners are documented, and F3 has an actual task ID rather than a merely intended classification.

**Trade-offs:** no blanket dependency force-fix, speculative service rewrite, new identity implementation, or global strictness migration in this audit. Do not widen every release filter to every repository file. Retain legitimate standalone locks until ownership is known. Avoid intrusive production tests and unsafe local execution of truncating integration fixtures; CI's isolated Postgres service is the intended boundary. No security/product code is put into the behavior-preserving code-garden lane.
