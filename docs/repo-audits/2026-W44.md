### Code quality, correctness and testing

#### F2: Akahu transaction continuation is discarded — High

**Fact:** the list response type declares `cursor.next` (`services/budget-api/src/services/akahuClient.ts:10`), but `akahuGetTransactions` performs one fetch and returns only `json.items` (`services/budget-api/src/services/akahuClient.ts:152`, `services/budget-api/src/services/akahuClient.ts:170`). A Node 24 execution of the actual client with a mocked fetch returning one item and `cursor.next='page-two'` produced `calls=1`, `returnedIds=['page-one']`. The sync route consumes that array and then updates `lastSyncedAt` (`services/budget-api/src/routes/akahu.ts:108`, `services/budget-api/src/routes/akahu.ts:292`); subsequent sync defaults use a seven-day overlap (`services/budget-api/src/routes/akahu.ts:23`, `services/budget-api/src/routes/akahu.ts:102`). The inspected sync test mocks the entire provider client (`services/budget-api/test/akahuSync.test.ts:39`), so those route fixtures cannot exercise real cursor traversal.

**Consequence/judgment:** if the provider supplies additional pages, the current client drops them. Advancing the checkpoint may leave older omitted records outside the next overlap, producing incomplete financial history. Actual provider page boundaries, affected records and production impact were not verified; the severity reflects potential financial completeness failure, not a confirmed incident.

**Classification:** `tracked-research-task`. ➡️ Tracked by task db74f2ed (`db74f2ed-ca01-4415-a1fe-0f56482e28f7`), research complete. ➡️ Tracked by task a37b31c9 (`a37b31c9-1ddc-4732-b8c8-9968726c9c0c`) for implementation. Establish the current provider contract, completion invariant and recovery needs before implementing. This is not garden-safe: pagination, checkpoint semantics and potential backfill affect persisted financial data. Research produces `brain/research/akahu-sync-completeness-and-deadlines.md`; the implementation task carries the required design at `docs/specs/budget-akahu-pagination-deadlines-tech-design.md`. ✅ [PR #889](https://github.com/Stoffer-Industries/sindustries/pull/889)

### Performance and operations

#### F3: Akahu requests have no application deadline — Medium

**Fact:** all five calls use `fetch` without a supplied abort signal or per-operation deadline (`services/budget-api/src/services/akahuClient.ts:63`, `services/budget-api/src/services/akahuClient.ts:86`, `services/budget-api/src/services/akahuClient.ts:109`, `services/budget-api/src/services/akahuClient.ts:152`, `services/budget-api/src/services/akahuClient.ts:175`). Response-body reads are awaited separately. The mocked transaction-client execution recorded `hasSignal=false`; the sync route awaits three provider operations in `Promise.all` (`services/budget-api/src/routes/akahu.ts:108`).

**Consequence/judgment:** a slow provider can retain a sync request beyond the application's intended response budget; one stalled member delays the whole result. Runtime/network defaults may impose their own timeouts, so this is not a claim that sockets wait forever. Blindly retrying token exchange or refresh would introduce another correctness risk.

**Classification:** `tracked-research-task`. ➡️ Tracked by task db74f2ed (`db74f2ed-ca01-4415-a1fe-0f56482e28f7`), shared with F2 because page traversal needs a bounded overall sync budget. ➡️ Tracked by task a37b31c9 (`a37b31c9-1ddc-4732-b8c8-9968726c9c0c`) for implementation. Specify cancellation, body-read timeout and safe retry rules before changing observable behavior. ✅ [PR #889](https://github.com/Stoffer-Industries/sindustries/pull/889)

#### F4: Analytics reads materialize all matching events — Medium

**Fact:** task history has an uncapped `findMany` (`services/tasks-api/src/routes/featureTaskAnalytics.ts:225`). Weekly analytics limits weeks to 52 but not row count (`services/tasks-api/src/routes/featureTaskAnalytics.ts:261`, `services/tasks-api/src/routes/featureTaskAnalytics.ts:308`); percentile calculation copies and sorts arrays (`services/tasks-api/src/routes/featureTaskAnalytics.ts:279`).

**Consequence/judgment:** memory/query cost grows with event volume. No present latency or capacity incident was measured; truncating results would silently alter statistics.

**Classification:** `tracked-research-task`. ➡️ Tracked by task c1f6fd7f (`c1f6fd7f-7fe4-4662-ab19-386444de7a5e`), retained from W43 F4, research complete. ➡️ Tracked by task 75032fad (`75032fad-1b5d-4409-af5f-c803166b7933`) for implementation. Measure workload before choosing aggregation or pagination; neither is assumed garden-safe; the implementation task carries the required design at `docs/specs/tasks-api-analytics-bounded-queries-tech-design.md`. ✅ [PR #893](https://github.com/Stoffer-Industries/sindustries/pull/893)

## Improvement Strategy

1. **Make completion truthful.** A financial sync is complete only after the selected interval's pages are exhausted and persisted. Define partial-failure/checkpoint behavior before changing code. Done: multi-page, repeated-cursor, empty-page and later-page-failure fixtures demonstrate the chosen invariant; assess recovery for older omissions.
2. **Bound external work.** Introduce an explicit per-call and overall sync budget rather than depending on transport defaults. Done: delayed headers and delayed bodies terminate within configured budgets, without unsafe retries or checkpoint advancement on incomplete ingestion.
3. **Enforce what CI claims.** Select a supported fail-closed secret scanner and baseline API type checking. Done: a synthetic credential fixture blocks the gate, scanner faults fail visibly, and an intentional compiler error is rejected in each adopted API lane.
4. **Measure before optimizing.** Obtain analytics row-count, latency and memory baselines before altering API semantics. Done: documented representative workloads and budgets, with numerically equivalent results for any proposed aggregation.

Trade-offs: keep the existing Express/Prisma/React boundaries and mixed automation runtimes. Do not add arbitrary analytics caps, rewrite the provider integration, auto-backfill bank records, change intentional read-auth policy or enable blanket TypeScript strictness during an audit. Do not create duplicate tasks for open research. All actionable findings here are behavioral/security/research work, not code-garden cleanup; there are no new garden-safe findings to manufacture.
